Export lockfile artifacts to the Maven local repository

Usage: raeva export-m2 [OPTIONS]

Options:
      --dry-run
          Show what would be exported without writing

      --overwrite
          Overwrite existing files in the target repository

      --link <STRATEGY>
          How to place each file: copy, hardlink, or symlink. A link shares the file in raeva's store, so a Maven write to it corrupts the store
          
          [default: copy]

      --m2-path <PATH>
          Write to this local repository instead of the configured one

      --with-sources
          Also fetch/export -sources classifier JARs

      --with-javadocs
          Also fetch/export -javadoc classifier JARs

  -h, --help
          Print help (see a summary with '-h')

Global Options:
  -C, --project-root <PATH>
          The project directory, which holds the root pom.xml
          
          [default: .]

  -v, --verbose...
          Show more output for debugging (repeatable; set RUST_LOG to override verbosity entirely)

  -q, --quiet
          Show only essential output (no spinners or progress bars)

      --json
          Produce machine-readable JSON output (implies --quiet)

      --offline
          Use cached data and file repositories only; commands that need the network fail

  -s, --settings <FILE>
          Read this Maven settings file instead of ~/.m2/settings.xml, as mvn -s does

  -P, --activate-profiles <IDS>
          Activate Maven profiles, or deactivate one written !id, as mvn -P does (repeatable)

  -D, --define <NAME=VALUE>
          Set a Maven user property, as mvn -D does (repeatable)

Copies the locked dependencies, their POMs, parents and imported BOMs from raeva's store into a Maven local repository, so `mvn -o` finds them.

The destination is --m2-path, else -Dmaven.repo.local given to raeva, else local_repository in the user config.toml, else <localRepository> in ~/.m2/settings.xml, else ~/.m2/repository. local_repository in raeva.toml and -Dmaven.repo.local in .mvn/maven.config are ignored here, with a warning. ${user.home} and ${env.NAME} in a configured path are expanded, and a relative path is resolved against the current directory, as Maven does.

For a locked offline build, export to an empty directory of its own outside the project, as `raeva --help` shows. Its version lists then name only the locked versions, so `mvn -o` resolves what raeva.lock pins, also with a -Dmaven.repo.local.tail. Into the local repository other builds share, it adds the locked versions, removes nothing, and warns that `mvn -o` there is not a locked build.

Build plugins and extensions are not exported: fill another repository with one online Maven run and pass it as the tail. Reactor modules are not exported either: run `mvn -o` at the reactor root, or with -pl <module> -am.

Examples:
  raeva export-m2 --m2-path "$(mktemp -d)/deps" # Export to a new repository of its own
  raeva export-m2 --dry-run           # Show what would be exported
