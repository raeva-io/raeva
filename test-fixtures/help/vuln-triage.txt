Record in an OpenVEX file that a finding does not affect a module

Usage: raeva vuln triage [OPTIONS] --justification <JUSTIFICATION> --vex <FILE> <ID>

Arguments:
  <ID>
          The advisory id or one of its aliases

Options:
      --justification <JUSTIFICATION>
          Why the finding does not affect the module
          
          [possible values: component_not_present, vulnerable_code_not_present, vulnerable_code_not_in_execute_path, vulnerable_code_cannot_be_controlled_by_adversary, inline_mitigations_already_exist]

      --module <MODULE>
          Select a module by root-relative pom.xml path or unique groupId:artifactId

      --platform <OS-ARCH>
          Report only this recorded platform (default: all platforms)

      --jdk <VERSION>
          Report only this exact recorded target JDK (default: all JDKs)

      --include-test
          Include dependencies reached only on the test classpath

      --component <COMPONENT>
          The dependency, as its purl or as the table shows it

      --vex <FILE>
          The OpenVEX file to add the statement to

      --impact-statement <TEXT>
          Explain the justification

      --author <NAME>
          The document author, needed when the file does not exist

      --product-version
          Record the statement for this module version only, not for every version

  -h, --help
          Print help (see a summary with '-h')

Global Options:
  -C, --project-root <PATH>
          The project directory, which holds the root pom.xml
          
          [default: .]

  -v, --verbose...
          Show more output for debugging (repeatable; set RUST_LOG to override verbosity entirely)

  -q, --quiet
          Show only essential output (no spinners or progress bars)

      --json
          Produce machine-readable JSON output (implies --quiet)

      --offline
          Use cached data and file repositories only; commands that need the network fail

  -s, --settings <FILE>
          Read this Maven settings file instead of ~/.m2/settings.xml, as mvn -s does

  -P, --activate-profiles <IDS>
          Activate Maven profiles, or deactivate one written !id, as mvn -P does (repeatable)

  -D, --define <NAME=VALUE>
          Set a Maven user property, as mvn -D does (repeatable)

The finding must be unique among the scanned modules and dependencies.
When the advisory affects several, --module and --component pick one.
An identical statement already in the file leaves it unchanged; a
different one for the same finding fails and changes nothing.

The statement names the module without its version, so it still applies
after a release; the dependency version is exact, so upgrading or
downgrading the dependency ends it. --product-version names this module
version only.
