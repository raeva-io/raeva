Scan locked dependencies for known vulnerabilities

Usage: raeva vuln [OPTIONS]
       raeva vuln <COMMAND>

Commands:
  triage  Record in an OpenVEX file that a finding does not affect a module
  help    Print this message or the help of the given subcommand(s)

Options:
      --module <MODULE>
          Select a module by root-relative pom.xml path or unique groupId:artifactId

      --platform <OS-ARCH>
          Report only this recorded platform (default: all platforms)

      --jdk <VERSION>
          Report only this exact recorded target JDK (default: all JDKs)

      --include-test
          Include dependencies reached only on the test classpath

      --format <FORMAT>
          Output format: table or sarif
          
          [default: table]
          [possible values: table, sarif]

      --fail-on <SEVERITY>
          Exit 1 for a finding at this severity or above; unknown always counts, and never only reports
          
          [default: high]
          [possible values: any, low, medium, high, critical, never]

      --vex <FILE>
          Suppress the findings an OpenVEX file marks not_affected (repeatable)

      --baseline <FILE>
          Count only findings new against this lockfile toward --fail-on

  -h, --help
          Print help (see a summary with '-h')

Global Options:
  -C, --project-root <PATH>
          The project directory, which holds the root pom.xml
          
          [default: .]

  -v, --verbose...
          Show more output for debugging (repeatable; set RUST_LOG to override verbosity entirely)

  -q, --quiet
          Show only essential output (no spinners or progress bars)

      --json
          Produce machine-readable JSON output (implies --quiet)

      --offline
          Use cached data and file repositories only; commands that need the network fail

  -s, --settings <FILE>
          Read this Maven settings file instead of ~/.m2/settings.xml, as mvn -s does

  -P, --activate-profiles <IDS>
          Activate Maven profiles, or deactivate one written !id, as mvn -P does (repeatable)

  -D, --define <NAME=VALUE>
          Set a Maven user property, as mvn -D does (repeatable)

Formats:
  table    Human-readable findings (default); raeva --json prints them as JSON
  sarif    SARIF 2.1.0 for code scanning systems

Exit codes:
  0  Scan completed with no findings at or above the threshold
  1  Scan completed with findings at or above the threshold
  2  Scan did not complete, for a cause with no more specific code
  3  Invalid configuration, a missing or invalid raeva.lock, --baseline, or --vex file,
     or an untrusted OSV certificate
  4  The OSV API could not be reached, or answered 429, 502, 503 or 504
  7  raeva.lock is out of date for the project or its configuration

A scan that could not fetch every record OSV named is incomplete: it
prints the findings it has and exits with the code of the fetch errors,
never 0 or 1.

Unknown severity (no CVSS score) meets every --fail-on threshold. A CVSS
score of 0.0 is None, which only any meets. --fail-on never reports the
findings and exits 0, but an incomplete scan or invalid configuration still
fails. Dependencies a module reaches only on its test classpath are not
scanned unless --include-test is given. A finding that a --vex file marks not_affected is shown as
suppressed and does not count toward --fail-on. The Fixed column is the
nearest version above the locked one that the advisory names as fixed.

With --baseline, only new findings count toward --fail-on. A finding is
existing when the same exact dependency purl and OSV id occur anywhere in
the baseline, in any of its targets and modules. Only the current inventory
is queried. Every current finding is shown as New or Existing. A record
fetch failure fails the scan. The baseline does not need to match the
current project POMs or targets.

By default, scan every recorded platform and JDK, deduplicated by exact
purl. --platform and --jdk restrict the scan to recorded targets;
--jdk matches the exact target version. Missing targets fail without a
host fallback. --include-test includes test-only dependencies in both
inventories. VEX applies to every selected module identity.

Examples:
  raeva vuln
  raeva vuln --module app/pom.xml
  raeva vuln --module com.acme:app
  raeva --json vuln
  raeva vuln --format sarif
  raeva vuln --fail-on critical
  raeva vuln --fail-on never
  raeva vuln --vex vex.json
  raeva vuln --baseline base.lock
  raeva vuln --platform linux-x86_64 --jdk 21
  raeva vuln --include-test
  raeva vuln triage GHSA-xxxx-xxxx-xxxx --justification vulnerable_code_not_in_execute_path --vex vex.json --author "Acme Security"
